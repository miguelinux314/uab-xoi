    [7] Capa 2: Comunicació de xarxa (LAN)¶

    Capacitats¶

    Els protocols de capa 2 permeten que diversos dispositius intercanviïn missatges i s’identifiquin entre ells dins d’una xarxa local (LAN (xarxa d’àrea local)). Amb els protocols de capa 2 no es pot contactar directament amb dispositius de fora de la LAN.

    La capa 2 abstreu les capes superiors (incloses les aplicacions d’usuari) dels detalls específics del maquinari connectat. Això fa més fàcil (és a dir, més barat) escriure el codi una vegada i executar-lo a tot arreu.

    Els missatges de capa 2 tenen una longitud limitada. La quantitat màxima de dades de payload (càrrega útil) que es pot inserir en un protocol de capa 2 s’anomena unitat màxima de transmissió (MTU), p. ex., \(1500\) bytes per a Ethernet.

    Alguns protocols de capa 2 també poden oferir autenticació d’usuaris i protecció criptogràfica; Wi-Fi n’és un exemple destacat, tot i que les xarxes amb cable també poden fer servir, p. ex., IEEE 802.1X.

    Protocols¶

    S’han definit i s’estan definint molts protocols dins de la capa 2. Els més importants avui dia són:

    • Ethernet (IEEE 802.3), tractat a la Section 7.2.

    • Wi-Fi (p. ex., IEEE 802.11be, també conegut com a Wi-Fi 7, del 2024).

    Dins de TCP/IP, la capa 2 encapsula les PDUs dels protocols següents (tots dos tractats al capítol 8):

    • Datagrames IPv4 i IPv6.

    • Missatges ARP.

    Nota

    L’ordre ip link mostra les teves interfícies i permet configurar-les, incloent-hi l’adreça MAC.

    El teu sistema operatiu normalment assigna automàticament noms interns a les interfícies segons el seu tipus, p. ex., eth0 o wlan1. Normalment es poden canviar els noms de les interfícies, perquè aquests noms no formen part de TCP/IP; només es fan servir dins d’aquell sistema operatiu.

    Adreçament de capa 2¶

    En la majoria de tecnologies LAN, les adreces de capa 2 són identificadors numèrics únics per a cada dispositiu dins de la LAN. El tipus més habitual són les adreces MAC d’Ethernet (tècnicament EUI-48), que ocupen \(6\) bytes (és a dir, \(48\) bits). També es fan servir fora d’Ethernet, p. ex., a Wi-Fi i Bluetooth.

    Les adreces MAC es presenten a les persones sovint en el format següent:
    01:23:45:67:89:ab. Algunes adreces tenen un significat especial i no són identificadors de dispositiu vàlids. Per exemple, ff:ff:ff:ff:ff:ff és l’adreça de broadcast (difusió), que vol dir “tothom a la LAN”. A més, 00:00:00:00:00:00 es fa servir per representar una adreça MAC desconeguda (consulta l’RFC 9542 per a una descripció completa de les adreces MAC reservades, incloses les de multicast (enviament a un grup)).

    El maquinari de xarxa ve amb una adreça MAC integrada, única i predefinida, a punt per fer-se servir. Les MAC dels dispositius es poden configurar a nivell del sistema operatiu, però es mantenen constants mentre s’utilitzen.

    [7.2] Protocol de capa 2 Ethernet¶

    Format de paquet¶

    La capa 2 d’Ethernet defineix el format següent, que es fa servir en tots els missatges. Els paquets d’aquest tipus s’anomenen frames (trames):

    • MAC de destinació: l’adreça MAC del dispositiu de destinació, o ff:ff:ff:ff:ff:ff per a broadcast.

    • MAC d’origen: la MAC del dispositiu que envia el frame.

    • Tipus de payload: identificador del protocol encapsulat al payload,
      p. ex., 0x0800 \(\rightarrow\) IPv4, 0x86DD \(\rightarrow\) IPv6 i 0x0806 \(\rightarrow\) ARP. De vegades s’anomena EtherType.

    • Payload: contingut que es demana enviar, p. ex., per part d’IPv4 o ARP. La longitud màxima d’aquest camp, la MTU, és de \(1500\) bytes per a Ethernet.

    • Quantes adreces MAC diferents hi ha a Ethernet (incloent-hi els blocs reservats)?

    • N’hi ha prou perquè cada dispositiu amb connexió a internet de la Terra tingui una MAC única?

    Exercici 7.2

    És vàlid el frame següent?

    c2 21 90 15 bc b6 42 40 e5 f7 5e 32 42 77 57
    03 ca 27 6b 1f 97 e9 02 7f 80 fa 8b 61 59 2a
    81 b6 73 b0 b4 e1 75 4f ef 40 dd 9f 3c 48 67

    Funcionament¶

    Els missatges dins d’una LAN Ethernet normalment s’envien en mode unicast (enviament a un únic destinatari), és a dir, són missatges d’un a un. Això permet als switches (commutadors) minimitzar el consum d’energia i d’amplada de banda. En unicast, el node del dispositiu d’origen ha de conèixer la MAC de la destinació.

    Ethernet també admet broadcast a tots els nodes de la LAN. En aquest cas, l’adreça MAC de destinació ha de ser ff:ff:ff:ff:ff:ff. Quan un dispositiu rep un frame, el descarta tret que el camp de MAC de destinació del frame sigui idèntic a la seva pròpia adreça MAC, o de broadcast.

    Un node també descartarà un frame amb un camp de tipus de payload (EtherType) no admès. Si el tipus de payload és admès, es fa servir per decidir quina part del sistema operatiu rep el missatge, p. ex., la pila IPv4 o el subsistema ARP.

    Continuant l’exemple de la figura anterior, la targeta de xarxa del node B rep un frame que comença amb els bytes següents. L’hauria d’acceptar B?

    Exercici 7.4

    Els scripts següents mostren com enviar i rebre frames Ethernet en brut. El client envia \(5\) frames idèntics d’EtherType 0x1234 i després acaba. El servidor espera fins que rep \(5\) frames Ethernet d’aquest tipus (comprovat a les línies 12-13) i després acaba.

    • Canvia l’adreça MAC i el nom d’interfície del client pels teus.

    • Fes que el servidor rebutgi els frames que no li són adreçats.

    • Amplia aquests scripts per implementar una aplicació senzilla amb capacitats LAN.
      Exemples suggerits:

      • Un servei d’eco de capa 2 que distingeixi entre peticions i respostes.

      • Un xat peer-to-peer (de parell a parell) de capa 2 que inclogui el sobrenom de l’origen en tots els missatges.

      • Un servei de calculadora de capa 2 que admeti operacions aritmètiques bàsiques
        (+, -,*, divisió entera // i, opcionalment, divisió /).

    • Què falta perquè la teva aplicació es pugui connectar a la resta d’Internet més enllà de la teva LAN?

    snippets/ethernetclient.py

    import socket

interface_name = "wlp5s0"  # Needs manual configuration
source_mac = bytes([0x00, 0x11, 0x22, 0x33, 0x44, 0x55])
destination_mac = bytes([0xff, 0xff, 0xff, 0xff, 0xff, 0xff])
packet_type = bytes([0x12, 0x34])
payload_data = bytes([0x78, 0x6f, 0x69, 0x20, 0x75, 0x61, 0x62])

# This socket sends Layer 2 packets directly.
s = socket.socket(family=socket.AF_PACKET, 
                  type=socket.SOCK_RAW, 
                  proto=socket.ntohs(socket.ETH_P_ALL))
s.bind((interface_name, 0))

for i in range(5):
    frame = destination_mac + source_mac + packet_type + payload_data
    s.send(frame)
    print(f"Sent frame {i + 1}/5: {len(frame)=}, {payload_data=}.")

    snippets/ethernetserver.py

    import socket

interface_name = "wlp5s0"  # Needs manual configuration

# This socket receives Layer 2 packets directly.
s = socket.socket(family=socket.AF_PACKET, 
                  type=socket.SOCK_RAW, 
                  proto=socket.ntohs(socket.ETH_P_ALL))
s.bind((interface_name, 0))

valid_frames = 0
while valid_frames < 5:
    frame = s.recv(1514)
    if frame[12:14] != bytes([0x12, 0x34]):
        continue
    valid_frames += 1
    print(f"Received frame {valid_frames + 1}/5, {len(frame)} bytes. "
          f"Payload: {frame[14:]!r}")

    Nota

    Hauràs d’executar aquests scripts amb privilegis, p. ex., amb sudo. Com a alternativa, pots afegir de manera permanent les capacitats CAP_NET_RAW al teu binari de python amb

    sudo setcap cap_net_raw+ep ./venv/bin/python.

    Després, pots executar ./venv/bin/python script.py directament sense sudo.
